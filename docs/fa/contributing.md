# مشارکت در توسعه

تغییر را با دامنهٔ مشخص روی شاخهٔ جدا انجام دهید و در درخواست تغییر، مسئله، رفتار جدید و روش بررسی را بنویسید. این پروژه بر پایهٔ DanWahlin/ai-agent-board است؛ مجوز MIT و انتساب بالادستی را حفظ کنید. [منشور رفتاری](../../CODE_OF_CONDUCT.md) برای همهٔ مشارکت‌کنندگان برقرار است.

[بازگشت](../../README.fa.md) · [راهنمای انگلیسی](../../CONTRIBUTING.md)

## آماده‌سازی و بررسی

Node.js نسخهٔ 22 یا بالاتر، npm نسخهٔ 10 یا بالاتر و Git لازم است. ابزار عامل را جدا نصب و احراز هویت کنید. فایل تنظیم را از نمونهٔ هر workspace بسازید؛ کلید واقعی باید بیرون مخزن بماند.

</div>

```bash
npm ci
cp packages/server/.env.example packages/server/.env
cp packages/client/.env.example packages/client/.env
npm run dev
```

<div dir="rtl">

تابلو در [localhost:8081](http://localhost:8081) است. پیش از درخواست تغییر، بررسی‌های مرتبط را اجرا کنید:

</div>

```bash
npm run build:shared
npm test -w @ai-agent-board/server
npm run build:server
npm run build:client
npx playwright install --with-deps chromium
npm run gate:required
```

<div dir="rtl">

دروازهٔ الزامی، آزمون قرارداد سرور، یکپارچه‌سازی Hermes، ساخت و آزمون مرورگر را اجرا می‌کند. نبود محیط E2E موفقیت نیست؛ نتیجهٔ واقعی و محدودیت محیط را گزارش دهید. ارزیابی زندهٔ مدل از آزمون قطعی جداست.

## ساختار و تغییر مسیریاب

رابط در `packages/client`، سرور در `packages/server` و قراردادها در `shared` هستند. نام workspaceها همچنان `@ai-agent-board/*` است. TypeScript سخت‌گیرانه و لایهٔ repository را حفظ کنید؛ تغییر قرارداد باید در هر دو پایگاه SQLite و PostgreSQL سازگار باشد.

تغییر مسیریاب به آزمون حساسیت پیش‌فرض محرمانه، اجازهٔ صریح `public` برای مسیر رایگان، ریشه‌های محرمانه و تقدم عامل و سطح نیاز دارد. اگر رفتار ارتقا یا مسیر جایگزین عوض می‌شود، همان رفتار را هم آزمون کنید. برای ارائه‌دهنده، سهمیه، لغو، جابه‌جایی بین ارائه‌دهندگان و رد فایل کلید ناامن را پوشش دهید. جزئیات در [مرجع مسیریاب](../ROUTING.md) آمده است.

## پیام تغییر و درخواست بازبینی

پیام commit را کوتاه و امری بنویسید؛ قالب `type: summary` توصیه می‌شود، مانند `fix: reject confidential free routing`. تغییرهای نامرتبط را جدا کنید. در PR مسئله، رفتار نهایی، آزمون و محدودیت‌ها را بیاورید. راهنمای انگلیسی و فارسی را با هم به‌روز کنید؛ شناسه‌ها در قالب کد و بلوک فرمان بیرون بخش راست‌به‌چپ باشند.

گزارش عمومی فقط باید نمونهٔ ساختگی داشته باشد. کلید، مسیر شخصی، محتوای مخزن خصوصی، خروجی خام و پایگاه داده را ثبت نکنید. آسیب‌پذیری را طبق [سیاست امنیت](../../SECURITY.md) خصوصی گزارش کنید.
